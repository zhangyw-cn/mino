# Interactive States Unification Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Unify cursor, hover, active, focus-visible, and disabled feedback across Mino-owned Workbench and Markdown viewer controls via shared tokens and four explicit variants.

**Architecture:** Define CSS variables and `.mino-*` variant classes in `web/src/styles/index.css` (Workbench) and mirror them in `web/src/md/viewer.css`. Components attach the variant class and drop redundant interaction utilities. Selection uses `.mino-selected` on list rows so hover cannot override the selection fill. Mermaid canvas keeps grab/grabbing; preview iframe user content is untouched.

**Tech Stack:** React 19, TypeScript, Vite, Tailwind 4 (`@layer components` for variants), Vitest, Testing Library. Embedded UI via `cd web && npm run build` → `internal/ui/dist`.

## Global Constraints

- Spec: `docs/superpowers/specs/2026-09-25-mino-interactive-states-design.md`
- Variant class names (exact): `mino-icon-button`, `mino-list-row`, `mino-chrome-button`, `mino-status-chip`
- Selection marker class (exact): `mino-selected`
- Tokens: `--mino-focus: #0078d4`, `--mino-hover-bg: #2a2d2e`, `--mino-disabled-fg: #6e6e6e`
- Selection fill: `#04395e` with white text on selected list rows
- Status chip hover: `rgba(255, 255, 255, 0.15)` (same as current `hover:bg-white/15`)
- Focus ring only on `:focus-visible`; disabled covers `:disabled` and `[aria-disabled="true"]`
- No global bare-`button` forced styles; no theme engine; no new npm packages
- Prefer TDD; commit after each task
- After UI source that ships in the binary changes, run `cd web && npm run build`
